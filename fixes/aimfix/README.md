# aimfix: artillery aims at the middle of the target unit

**Problem.** Ordered to fire at an enemy unit, each artillery piece aims at one soldier of that
unit, roughly the soldier in front of the gun. A battery that does not stand squarely in front of
its target therefore aims at the near end of the enemy line. Spread still lands some shots in the
middle, but most of the battery's fire falls on the edge of the unit, where it hits the fewest men.

**Fix.** Every artillery shot at a unit is aimed at the soldier standing nearest to the unit's
centre of mass (the centroid of its living men). Aim height, spread, reload and everything else
stay the game's own.

State: dev build only (2026-10-18), not in a public release yet.

## Measured (replay `Artilery_shooting`)

Three batteries of four Armstrong guns fire at three advancing 200-man line infantry units from
about 480 down to 370 m. Same replay, fix off and on, with the research probe
(`tests/compare_runs.py`):

| | Fix off | Fix on |
|---|---|---|
| Shots fired | 60 | 60 |
| Aim point to the target unit's centroid, median (max) | 22.0 m (28.0) | 0.4 m (2.2) |
| Aim point along the 53 m frontage (0 = an end, 1 = the middle), median | 0.17 | 1.00 |
| Shots aimed at the outer tenth of the line | 47 % | 0 % |
| Enemy men lost, three units | 247 | 320 |

The fix changed the target soldier 676 times (once the game's pick was already the centre one) and
never failed its unit check. The replay is deterministic: a repeat gave the same numbers. With the
fix on the battle no longer follows the recording exactly (the casualties differ), as with every
fix that changes the simulation.

## How it works

The engine hands an artillery piece its target in a fire action. The first time that action
updates (`FUN_1047fd90`), it copies a target record (soldier + offset) into the gun, and the gun
then turns, aims and fires at that soldier. The fix hooks the entry of `FUN_1047fd90` and, while
the record has not been handed over yet, replaces the soldier with the one nearest to the centroid
of the same unit. It only acts when

- the shooter belongs to one of the six engine (artillery) classes, recognised by the engine's
  own fire-order method in its vtable (infantry and cavalry never match),
- the target is a soldier (not ground, a building or a point), and
- the soldier is found in his unit's soldier array.

Details: [ARCHITECTURE.md](ARCHITECTURE.md), engine decode in
[docs/re/artillery_aim_x86.md](../../docs/re/artillery_aim_x86.md).

## Dev build

Built into the dev `dinput8.dll` with CMake option `FIX_AIMFIX` (on by default), next to the path
fix. The fix is on at launch. **U** switches it off and on again at any time (only while the game
window has the focus): a system "asterisk" sound for on, the default beep for off. The log names
each switch (`aimfix: U, fix ON` / `OFF`).

| Environment | Effect |
|---|---|
| `AIMFIX_OFF=1` | start with the fix off (hook installed, changes nothing), for A/B runs |
| `AIMFIX_PROBE=1` | research capture into `<game>\aimfix_runs\<stamp>\` (two extra hooks; see `src/aimfix.cpp`) |
| `AIMFIX_WATCH=1` | with the probe: write watchpoint on the first four guns' target records |

Unattended A/B runs with the autorun tool: [docs/runbook.md](docs/runbook.md).

Log lines (in `<game>\pathfix_log.txt`): `aimfix: fix ON`, the installed hook, and at exit
`aimfix: artillery targets moved to the centre soldier N, already centre N, not a soldier N, unit
check failed N`. If the first 20 artillery targets all fail the unit check, the fix switches
itself off for the session (`aimfix: DISABLED ...`, the system error sound); U is refused from then
on.

Single player and replays only: a changed simulation desyncs multiplayer.

## Tests

`python fixes/aimfix/tests/run_tests.py` (also run by `test.bat`): maps the real
`empire.retail.dll`, loads the proxy and enters the game's `FUN_1047fd90` on fake fire actions,
guns and units. Runs `full` (18 checks: centre chosen for a line and a column, offset kept, handed-
over records, infantry shooters, building targets, lone survivors and broken unit links left
alone, counters, U switches it off and on again, unload restores the bytes), `off` (18, nothing
changes until U) and `selfcheck` (7, U refused after the switch-off).
